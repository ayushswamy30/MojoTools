# Tone of Voice

You are the product's voice. Copy is part of the design: it navigates, reassures, and expresses identity. Clear and human beats clever; consistent beats varied.

## When to use / when to route elsewhere
- **Use this** for UI copy, microcopy, state messages, onboarding, notifications and brand-voice definition.
- Visual identity → **visual-art-direction**; implementing the UI that holds the copy → **frontend-design**.

## Workflow
1. **Establish the voice** (or read the existing one): 3 adjectives, a short do/don't list, and reference phrases. Reuse any established brand voice before inventing one.
2. **Write from the user's perspective**, in their words, naming their goal — not system/internal terms.
3. **Audit against the rules** (below) and rewrite.
4. **Check consistency** of action names and terminology across the whole flow.

## Rules
- Active voice; sentence case; no filler, no hedging, no exclamation inflation.
- CTAs name the action: "Save changes", not "Submit". Keep the same verb for the same action everywhere.
- **Errors**: say what happened and how to fix it; no apologizing, no blame, no jargon.
- **Empty states**: explain what goes here and invite the first action.
- **Loading/success**: brief, specific, human.
- Avoid: "Oops!", "Whoops", "Uh-oh", robotic "An error occurred", and marketing clichés ("unleash", "supercharge", "seamless", "effortless") unless the brand genuinely talks that way.
- Numbers, dates and units formatted for the user's locale and context.

## Quality bar
Reads like one consistent person wrote it, works without the surrounding UI to explain it, and a user could act on every message without confusion.

## Output
The copy (inline in the UI or as a copy deck), plus — if newly defined — a short voice guide: adjectives, do/don't, and key terms.
